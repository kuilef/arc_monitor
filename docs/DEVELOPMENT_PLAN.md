# Сбор, обогащение и исследование Arc

Поручение: реализовать штатную конфигурацию, лимиты, покрытие и свежесть, затем этапы
2–5 исходного плана. Данные пользователя и предыдущий отчёт сохраняются.

## Решения

- Продолжаем в текущем checkout на отдельной ветке: здесь уже находятся ключ, база и
  незакоммиченные результаты предыдущей проверки. Их не переносим и не откатываем.
- CLI читает `.env` из текущего рабочего каталога или явно указанного файла; переменные
  окружения имеют приоритет, затем CLI-флаги. Никакого выполнения содержимого файла.
- История покрытия — интервалы, а не максимум checkpoint. Свежесть пустого успешного
  окна отличается от времени последнего события. Ошибка не создаёт coverage.
- Каждый HTTP-запрос, включая повтор, проходит частотный и количественный лимиты.
  Usage API даёт наблюдаемую квоту; локальный резерв на запрос защищает от задержки
  биллинга, но не объявляется точным финансовым потолком поставщика.
- Сбор блокируется для второго writer. Журнал переживает перезапуск. Ошибки сети
  повторяются с задержкой, ошибки конфигурации/квоты останавливают процесс явно.
- Исходные суммы Bitquery неизменны; RPC-подтверждение хранится отдельно с receipt,
  block hash и log index. Неоднозначные соответствия остаются неизвестными.
- Обогащение ограничено наблюдаемыми токенами/покупателями, имеет отдельные лимиты.
  Текущие holders не задним числом. Частичный список не объявляется полным.
  ERC20 interface / owner / proxy checks не означают аудит безопасности.
- Исследование использует временной hold-out, исключает пересечение токенов и label
  окон, сообщает объём пригодных данных, precision и ложные срабатывания.
  Исполнимость считается условной моделью при заданных комиссиях/проскальзывании,
  а неизвестные налоги/LP/продажа не становятся доказанной доходностью.
- Telegram выключен до исследования и настройки получателя; внешние сообщения
  в разработке не отправляются. WebSocket пока не нужен для ограниченного polling.

## Задачи и проверка

- [x] Конфигурация и контроль API: `config.py`, `budget.py`, Bitquery client;
  тесты env precedence, redaction, retries, delayed billing, request pacing.
- [x] Эксплуатация: `operations.py`, storage coverage gaps / run ledger, CLI status,
  polling recovery, API status. Проверки stale empty windows, holes, restart, writer lock.
- [x] Исследование: `evaluation.py`, временной split, фиксированные правила и ablation,
  execution sensitivity, сохранённый hold-out отчёт и gate уведомлений.
- [x] Обогащение: `enrichment.py`, реальные holders/funding/liquidity/contract evidence,
  RPC reconciliation. Проверки provenance, truncation, unknown и отсутствия look-ahead.
- [x] CCTP и creator history: подтверждённые transfer/message связи и scoped history;
  без утверждения о полной сети при ограниченном источнике.
- [x] Удобный запуск Windows и Telegram с gate, документация, полный pytest,
  ограниченная live-проверка, реальный исследовательский отчёт с текущими ограничениями.

Для каждой программной задачи сначала проверка, падающая на отсутствующей функции,
затем реализация и focused pytest. Полный набор запускается после интеграции.
Команда тестирования: `.\.venv\Scripts\python.exe -m pytest -q`.

## Прогресс

Начальное состояние: 80 тестов, live Bitquery/RPC доступны; данные неполные,
текущие риск/holders/funding/liquidity таблицы пусты. Результаты исследования
будут зависеть от реально полученного покрытия и зрелости горизонтов.


Инженерные задачи выполнены и проверены: 153 теста, live enrichment, CCTP 5/5,
реальный запуск Windows-задачи. Критерий подтверждения гипотезы не достигнут:
15 launch origins, 0 полных train/test наблюдений. Суточный резерв исчерпан,
Telegram gate закрыт. Факты и оставшиеся границы — в DELIVERY_2026-09-22.md.
